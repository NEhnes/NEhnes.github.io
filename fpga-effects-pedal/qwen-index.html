Problem Statement

— why this was built

Commercial guitar effects are expensive, inflexible, and require physical rewiring — while software DAWs and mobile modelers introduce audible processing latency.

Musicians choosing between a rack of analog stompboxes and a laptop-based rig accept either a fixed, un-reconfigurable signal chain or the buffer delays, jitter, and context-switching of a general-purpose OS. Real-time performance monitoring demands deterministic sample processing on a hard clock.

This project delivers a single, fully integrated FPGA-based solution: seven effects in hardware, reconfigurable signal chains, and practically zero latency — solving both the cost and the convenience problem without compromising audio determinism.

System Architecture

— two-domain SoC design

The design splits work by time-criticality: everything that must meet a hard deadline runs synchronously in FPGA fabric, while everything that needs flexibility runs on Linux — connected by AXI.

PL · Programmable Logic

Real-Time DSP Domain

All audio processing at 44.1 kHz in Verilog, chained via AXI-Stream with direct backpressure coupling — no intermediate buffering, deterministic per-stage latency.

  • 7 effect blocks + I²S transceiver + FIFO buffer
  • 100 MHz primary clock, timing closure >0.5 ns slack
  • CDC synchronizer chains on I²S-domain signals
PS · Processing System

Linux Control Plane

Dual-core ARM Cortex-A9 running PetaLinux with a terminal UI for parameter tuning. Low-frequency updates only — no real-time constraints on this side.

  • Effect parameters exposed as AXI-Lite memory-mapped registers
  • Single-cycle AXI writes; PL samples new values next clock edge
  • Active chain state, live parameter values, preset recall

Technical Implementation

— the engineering underneath

AXI-Stream Interconnect tvalid/tready

Cycle-by-cycle handshaking with direct backpressure coupling: tready propagates straight upstream, so the codec can rate-limit the entire chain. One clock of deterministic latency per stage, zero buffering overhead.

Fixed-Point Q-Format Math Q2.13 · Q0.15

Extended-precision intermediates (WIDTH+16 bits) with round-to-nearest then saturating truncation to range. Gains in Q2.13, clipping thresholds in Q0.15 — deterministic behavior across 16/20/24-bit configurations.

Hot-Swap Effect Chain crossbar MUX

Reconfiguration selected on the next clock edge: in-flight samples finish the old chain, new samples take the new path. ~2 cycles of latency per sample — inaudible — and no pops or clicks from abrupt switching.

6-Band Parametric EQ biquad IIR

Cascaded direct-form-II topology for numerical stability. Coefficients designed in MATLAB, quantized to Q-format, frequency response validated pre-synthesis against floating-point golden reference.

I²S Codec Interface ADAU1761

Hand-written I²S transceiver with clock generation and frame sync; I²C codec configuration. Sample clock derived in PL, with 44.1 kHz frame domain crossing handled by synchronizer chains.

Verification Icarus + MATLAB golden

Per-effect custom testbenches: swept frequency/amplitude injection, coefficient sweeps, saturation corner cases, and tvalid/tready backpressure toggling. Output verified against golden MATLAB models; VCD waveforms in GTKWave.

Design Challenges

— problems, tradeoffs, solutions
Challenge 01

Fixed-Point Saturation in Multi-Stage Gain

Problem: Cascading gain stages overflows even when final output is in range; naive per-stage saturation loses dynamic range.

Solution: Extended-precision intermediates (WIDTH+16) with rounding before truncation — saturation only at the output stage, preserving headroom through the chain.

Challenge 02

Glitch-Free Hot-Swap Mid-Stream

Problem: Reconfiguring the chain while samples are in flight causes pops and clicks; zero-latency switching trades off against audio continuity.

Solution: Synchronous crossbar-MUX routing — in-flight samples drain through the old path, new samples take the new path, costing ~2 cycles per sample.

Challenge 03

Resource Scaling Across Bit Widths

Problem: 16→24-bit cost isn't linear — DSP48 slices quantize in chunks, so utilization jumps unpredictably with precision.

Solution: Every arithmetic module genericized on WIDTH, with a post-synthesis LUT/DSP/BRAM tradeoff table at 16/20/24-bit depths documenting the scaling curve.

Challenge 04

Parameterized Delays in BRAM

Problem: Delay-line depth scales with both delay time and bit width — 24-bit samples consume proportionally more memory than 16-bit.

Solution: Buffers parameterized on bit depth and sample count so Vivado infers efficient BRAM; max delay per bit-depth configuration documented in the resource table.

Challenge 05

Verification Without Formal Methods

Problem: No UVM/SVA — custom testbenches risk missing saturation corner cases and underflow in divisions.

Solution: Exhaustive-range benches per effect (min/max/mid-scale, transitions, coefficient sweeps), post-synthesis simulation to catch timing violations, and golden-reference comparison against MATLAB.

Simulate an Effect Locally

Pure Verilog-2005/2009 — no SystemVerilog required. Each effect ships with a dedicated testbench that accepts real audio sample vectors.

# Compile the hard-clip effect and its testbench iverilog -g2009 -o hard_clip_tb.out hard_clip.v hard_clip_tb.v # Run simulation → VCD waveform for GTKWave vvp hard_clip_tb.out
