Why an FPGA?

— problem, target, constraint

Commercial guitar multi-effects are expensive, inflexible, and force musicians to physically rewire their signal chain for every configuration. Software modelers fix flexibility but buy it with audible processing latency — the sample-buffering tax of general-purpose OSes.

High-quality real-time audio demands deterministic timing: every sample must be processed on a predictable clock edge, with no OS jitter, no buffer underruns, and no phase drift between stages. That constraint is the domain of synchronous hardware, not general-purpose compute.

This project answers with a single, fully integrated Zynq-7000 SoC design: a chain of hand-coded Verilog DSP blocks in the PL fabric running at 44.1 kHz with direct backpressure coupling (~0 buffering between stages), and a Linux control plane on the ARM core for live parameter updates over AXI memory-mapped registers. Estimated end-to-end latency: 2–4 µs — vs. milliseconds for software.

Architecture

— two domains, one clock discipline

The design splits into a hard real-time domain (PL fabric) and a soft control domain (ARM + Linux). Audio never crosses a software boundary; parameters do — and only at ~44 k updates/sec against a 667 MHz core.

01

Programmable Logic (PL) Domain

All real-time DSP executes synchronously at 44.1 kHz in FPGA fabric: 53,200 LUTs, 220 DSP48 slices, 4.9 Mb block RAM. Stages are chained via AXI-Stream with direct backpressure coupling — no intermediate FIFO — so latency is one clock per stage plus processing delay, fully deterministic.

02

Processing System (PS) Domain

Dual-core ARM Cortex-A9 runs Petalinux. A terminal UI exposes effect parameters as memory-mapped 32-bit registers; writes land in the PL on the next clock cycle via single-cycle AXI-Lite transactions. PS has no real-time constraint — 44 k updates/sec is trivial at 667 MHz.

DSP Library

— seven hand-coded Verilog effects

EQ

6 cascading biquad IIR sections

Modeled in MATLAB, ported to fixed-point. Cascaded direct-form II topology for numerical stability; frequency response validated pre-synthesis.

Distortion

Asymmetric hard clipping

Independent +/− clipping thresholds (Q0.15) with pre-gain (Q2.13, 0–4×) and makeup gain. Emulates diode-style square waves.

Fuzz

Asymmetric clip + gain

1-pole lowpass tone control (8-bit coefficient) for high-frequency shaping, plus output compensation gain.

Delay

FIFO · BRAM-backed

Configurable buffer depth parameterized by both bit width and delay time in samples. Synthesis allocates BRAM efficiently.

Phaser

All-pass + LFO

Modulated all-pass filters with LFO driven synchronously at the sample rate — one sample of modulation per clock.

Chorus

Modulated delay

Modulated delay lines that smear timing slightly across the chain for the classic thickened, detuned image.

Noise Gate

Level-based gating

Threshold gating with hysteresis — holds the gate open through brief level dips to avoid chatter on decaying notes.

Fixed-Point Strategy

— one RTL core across bit depths

Every arithmetic module accepts WIDTH as a generic — 16, 20, or 24 bits per sample. Internal arithmetic widens to WIDTH+16 bits, rounds to nearest, then saturates back to the output width. One synthesis configuration produces the whole bit-depth family.

// Parameterized sample width — one core synthesizes 16 / 20 / 24-bit audio localparam WIDTH = 24; // Input/output sample width wire signed [WIDTH-1:0] sample; // Audio sample wire signed [WIDTH+15:0] temp; // Extended precision for multiplication // After rounding and truncation, result saturates back to WIDTH bits.

Q-Format Coefficients

Gain: Q2.13 Threshold: Q0.15 Tone / LFO: Q0.N

Q2.13 gives 0.0–3.99× gain with 13 fractional bits; Q0.15 normalizes ±1.0 for peak detection. Effect-specific coefficients adapt N to their numeric range.

Saturation & Rounding

Round-to-nearest Output clamp

Post-multiply: round-to-nearest, then truncate. Output clamps to [−2^(WIDTH−1), 2^(WIDTH−1)−1] — no overflow rollover, deterministic behavior across all bit depths.

Hot-swap via crossbar routing

Reconfiguration is a routing-layer event, not a DSP-layer event. On the next clock edge the crossbar MUX selects the new path; samples in transit finish the old chain cleanly.

Latency hit: ~2 cycles per sample during the transition — at 44.1 kHz against a 100 MHz clock, an inaudible 20 ns. No pops, no clicks, no dropped samples.

Design Decisions

— problems met with explicit tradeoffs
01 · Fixed-Point

Saturation in multi-stage gain

Cascaded pre-gain → post-gain stages can overflow even when the final output is in range. Saturating each stage loses dynamic range; saturating only at the end masks intermediate clipping.

Tradeoff Guard bits vs. silicon area.

Chosen: extended-precision intermediates (WIDTH+16) with rounding before truncation; saturation only at the output stage. Headroom preserved through the chain, deterministic output.

02 · Real-Time

Hot-swap without audio glitches

Reconfiguring the chain mid-stream leaves samples halfway through an old effect path. Abrupt switching causes pops and clicks.

Tradeoff Zero-latency reconfig vs. glitch-free audio.

Chosen: MUX/crossbar-level switch on the next clock edge; in-flight samples drain the old chain. ~2 cycles overhead — inaudible at 44.1 kHz.

03 · Resources

Bit-depth vs. fabric cost

16-bit audio uses fewer LUTs/DSP slices than 24-bit, but the relationship is non-linear — DSP48 slices quantize in chunks. Users need visibility to pick a bit depth.

Tradeoff Fidelity vs. resource cost.

Chosen: WIDTH as a synthesis-time generic, with a planned LUT / DSP48 / BRAM utilization table at 16 / 20 / 24-bit from post-synthesis reports.

04 · Memory

Parameterized delay buffers

Delay time scales with bit width — a 24-bit sample occupies 1.5× the BRAM of 16-bit for the same echo time.

Tradeoff Memory efficiency vs. maximum delay time.

Chosen: buffers parameterized by bit depth and delay time in samples; max echo times per bit-depth tier documented during profiling.
