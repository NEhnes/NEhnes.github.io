01 / The engineering problem

Real-time audio needs predictable behavior.

Software effects can be flexible, but their scheduling and buffering introduce latency and make timing less deterministic. Commercial hardware pedals, meanwhile, are often fixed-function and difficult to reconfigure.

This project moves the signal path into FPGA fabric: every sample is processed synchronously, effect modules are independently parameterized, and the chain can be rerouted without physically rewiring the system.

Recruiter takeaway The design demonstrates hardware/software co-design rather than an isolated RTL block: audio enters through I²S, crosses a deterministic PL pipeline, and is controlled by an ARM/Linux interface over AXI.
02 / System architecture

Two domains. One deterministic signal path.

The programmable logic owns the time-critical work. The ARM processing system handles configuration and user interaction without sitting in the audio loop.

03 / Delivered capability

What the platform already proves.

The core DSP pipeline is complete, with system control and post-synthesis profiling continuing as the project moves toward hardware validation.

CAPABILITY 01

Seven effects in one chain

EQ, distortion, fuzz, delay, phaser, chorus, and noise gate modules are synthesized for real-time operation on the Zynq-7000 SoC.

CAPABILITY 02

Hot-swappable routing

A crossbar and MUX-based routing layer switches the active effect path on a clock boundary while allowing in-flight samples to complete safely.

CAPABILITY 03

16 / 20 / 24-bit parameterization

Arithmetic modules accept a configurable sample width, making fidelity-versus-resource tradeoffs measurable instead of hard-coded.

CAPABILITY 04

Hardware/software integration

Linux-side control is exposed through memory-mapped AXI-Lite registers, separating low-frequency configuration from the deterministic sample path.

Current status: Core DSP pipeline complete; hot-swap testing, resource-utilization tables, end-to-end latency measurement, and Linux parameter UI are in progress.
04 / Technical depth

Design choices that matter in hardware.

  • Cycle-by-cycle AXI-Stream Direct tvalid/tready coupling propagates backpressure through the chain without inserting a FIFO between every effect.
  • Extended-precision arithmetic Intermediate values use WIDTH + 16 bits before rounding, truncation, and final saturation.
  • Stable fixed-point DSP Gain uses Q2.13, thresholds use Q0.15, and biquad filters use a cascaded direct-form-II topology.
  • Clock-domain discipline I²S sample-rate signals cross into the PL domain through synchronizer chains; AXI-Lite writes remain in the 100 MHz control domain.
// Direct backpressure coupling
assign i_tready = o_tready;
assign o_tvalid = i_tvalid;

// Extended precision before saturation
wire signed [WIDTH+15:0] temp;
// round → truncate → clamp to WIDTH bits

Representative RTL pattern: deterministic flow control and bounded numeric behavior.

05 / Verification mindset

Designed to be measured, not just demonstrated.

Fixed-point correctness

Amplitude and frequency sweeps, clipping boundaries, coefficient checks, and golden MATLAB comparisons validate the DSP math.

Protocol behavior

Dedicated Verilog testbenches exercise tvalid/tready toggling and verify that stalls propagate without dropping or duplicating samples.

Timing closure

Vivado synthesis and implementation target a 100 MHz PL clock, with timing summaries and post-synthesis checks used to close the design.

Hardware observability

A planned ILA integration will inspect stream handshakes, sample data, and parameter transitions on the deployed signal path.
